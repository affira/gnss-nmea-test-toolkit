# CLAUDE.md — GNSS NMEA Test Toolkit

Portfolio project: parse recorded NMEA 0183 logs from a GNSS receiver, check their
integrity, analyse receiver performance, and write a Markdown test report.
Python 3.11+, pytest, Robot Framework.

## Working rules

1. **Tests before or with every feature.** No production code lands without a test
   that exercises it. Prefer writing the failing test first.
2. **Run the full suite after every step** — both pytest and Robot Framework —
   not just the tests for the code that changed.
3. **Small commits after each green step.** One logical change per commit, and only
   when the full suite passes. Never commit on red.
4. **Never weaken a failing test** to make it pass (no loosened tolerances, deleted
   asserts, added skips/xfails, or changed expected values) unless the test itself is
   demonstrably wrong — and then say so explicitly and explain why.
5. **No invented data or results.** Never fabricate NMEA logs, test outcomes, metrics,
   or licence details. Real logs must have a confirmed reuse licence recorded in
   `data/SOURCES.md`. Synthetic logs are allowed only if clearly labelled synthetic
   (filename and header comment) and generated by a script in the repo.
   Report test results exactly as they ran.
6. **Ask before large changes** — new dependencies, restructuring modules, changing
   public interfaces or report format, or anything touching more than a few files.

## Conventions

- Layout: `src/` package, `tests/unit/` (pytest), `tests/acceptance/` (Robot),
  `data/` (logs + `SOURCES.md`).
- The parser and analyser must never crash on bad input: count and report problems.
- Commands:
  - `pytest`
  - `robot tests/acceptance`
